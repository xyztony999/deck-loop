# PRD — 初稿生成（C-02）

| 属性 | 值 |
|------|-----|
| 模块 | C-02 初稿生成（AA v1.0） |
| 功能类型 | 业务流程类（异步任务驱动） |
| 版本 | v1.1 |
| 日期 | 2026-10-08 |

## 1. 业务目标（G1）

把主题/需求转化为可迭代的初稿：先出结构化大纲供确认编辑，再整稿生成首个内容版本。解决「AI 一次成稿不可控」的痛点——大纲环节给用户结构控制权。

## 2. 功能范围（G2）

**做**：基于创作物主题/需求的大纲生成与编辑、大纲确认后发起整稿生成、生成任务进度跟踪/取消/失败重试、素材与品牌规范引用注入。

**不做**：跳过大纲直接整稿（首期不提供）；多人协作编辑大纲；生成内容的手工编辑（属后续版本编辑器范畴，首期不做）。

## 3. 角色（G3）

创作者：发起、编辑大纲、确认、跟踪、取消、重试。

## 4. 领域对象与关系（G4/G5）

- 大纲 Outline：Deck.draftOutline（值对象 JSON，节点树：章节/页主题/要点）。
- 生成任务 GenerationTask（子流程）：OUTLINE / FULL_GENERATE 两种 taskType。
- 产出：首个 DeckVersion（source=FULL_GENERATE）。

## 5. 业务字段（T1）

**大纲节点**：nodeId、标题、要点列表、页数建议、备注；**整稿生成入参**：大纲快照、品牌规范ID、素材ID集、期望篇幅档位。

**任务快照字段**：deckId、taskType、指令/入参快照、channelCode/modelCode（路由结果）、taskStatus、errorMsg、usageTokens、createdAt。

## 6. 被引用关系（T1a）

首个版本被 Deck.currentVersionId 引用（生成成功自动流转 DRAFT→ITERATING）；任务被生成过程跟踪面板消费。

## 7. 状态流转（T2）

GenerationTask：QUEUED→RUNNING→SUCCEEDED/FAILED/CANCELLED（domain-model.md §4.2）；成功回调→写新版本→Deck 状态自动流转（首个版本）。

## 8. 业务规则

1. 大纲必须经用户确认才可整稿生成；确认前可无限次重生成大纲（覆盖 draftOutline）。
2. 整稿生成成功自动创建版本并置为当前版本；失败不产生版本，可重试。
3. 同一创作物同时最多 1 个进行中任务（排队互斥）。
4. 引用素材必须为启用状态；品牌规范同理。
5. 模型路由按渠道偏好分档（大纲=快速档、整稿=质量档，可改）。

## 9. 非功能与异常（N1/N2）

- 整稿生成预期 30s~3min，任务流式反馈阶段进度；超时 10min 自动 FAILED。
- provider 失败自动重试 1 次（网关域职责），仍失败标记 FAILED 保留错误信息。
- 取消仅 QUEUED/RUNNING 可用；已成功不可取消。

## 10. 历史与审计（N4）

每次大纲生成/整稿生成留任务记录与用量；draftOutline 版本生成后转只读快照留存于版本指令快照。
