## 用户澄清结论（AskUserQuestion 四分叉）

| 分叉 | 决定 |
|------|------|
| "乱"的痛点 | ①页面内部各自为政 ②页面间结构不统一 ③密度与留白不一致 |
| 范围 | 全部七个页面（auth/deck/gen/adjust/assets/deliver/settings）一次到位 |
| 亮色模式 | 暗色为基准统一；亮色维持现状不动 |
| 深度 | 视觉统一 + 布局对齐；每页信息架构不变 |

## 现状审计（证据底座）

### 架构面：底座是干净的
- 引擎三组件（DlCardPage/DlListPage/DlDetailPage）**零硬编码色**，全走 token/变量。
- 主题双轨已锚定：theme.ts（Antd token，暗色三层 #141414/#1f1f1f/#262626）+ global.less（CSS 变量 + LESS 别名）。

### 杂乱源：各页面自定义组件脱离体系
| 文件 | 问题 |
|------|------|
| deliver/present.vue | **整页按亮色写死**（20+ 处 #fff/#f9fafb/#9ca3af/#d1d5db…），暗色模式下是白色孤岛——最大单一乱源 |
| adjust/DeckPreviewCanvas.vue | 画布白底属正当"文档表面"语义，但混入 #1890ff 旧蓝、控件未暗色化 |
| gen/OutlineEditor.vue | #1890ff（旧 Antd 蓝）+ #fff |
| assets/BrandkitEditDialog / PromptEditDialog | #1677ff（新 Antd 默认蓝）、#52c41a 原色硬编码 |
| adjust/VersionTreePanel.vue | #6b7280/#faad14/#52c41a 硬编码（有同值变量却直写） |
| 圆角 | 7 种值并存（2/3/4/6/8/10/12px）；token=8、卡片=10，三套并存 |
| 间距 | 12+ 种 padding 组合（6px~96px），无标尺 |

### 关键语义发现：三种蓝
**#6b8ab5（设计系统主色）/ #1890ff（旧 Antd）/ #1677ff（新 Antd 默认）** 同时存在——主色视觉分裂的直接原因。

## 核心设计决策（进入 D4 的输入）

1. **两个表面域**：应用 chrome（页面壳/侧栏/工具条/弹窗/表单）走暗色三层语言；**文档表面**（幻灯片预览/演示舞台/导出渲染的画布内容）保持白纸语义、不受主题影响——此前无人区分这两域，是"白岛"与"硬编码白"并存的根源。
2. 三蓝归一（唯一主色）、语义色全部 token 化、圆角三值制、间距 4px 基数标尺。
3. 页面骨架统一三段式：标题区 / 工具栏 / 内容区（engine 已有结构对齐，视图侧槽内容跟随）。

→ 产出：`01-solution/common-spec/07-ui-design-language.md`（唯一设计语言规范）+ `02-detailed/interaction/ui-unify-2026-10-21.md`（逐页对齐清单）。
