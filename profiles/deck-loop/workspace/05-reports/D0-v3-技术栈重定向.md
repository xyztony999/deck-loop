## 1. 决策表

| # | 决策点 | v3 结论 | 理由 |
|---|--------|---------|------|
| 1 | 后端语言/框架 | **Node.js + TypeScript + NestJS**（用户给的 node/python 二选一） | 与前端同语言（TS 类型可共享契约）；SSE/JSON 原生友好；NestJS 模块化与八域结构一一对应；内存占用 ~100-200MB（对比 JVM 数百 MB，直接回应 OOM 教训） |
| 2 | 数据库 | **MongoDB** | 版本内容快照本就是不可变 JSON 文档（天然文档形态）；十表模型映射为 collection + 嵌入策略；个人数据量级下无关系查询压力；容器内单实例 + 内存限额（wiredTigerCacheSize） |
| 3 | 部署 | **Docker Compose**（node + mongo 两容器）；边缘反代**沿用宝塔 Nginx**（部署域名的 DNS/站点/证书工作已就绪，不重复建设） | `docker compose up -d` 一条命令；内存限额显式声明（防再次 OOM：node `--max-old-space-size=256`，mongo cache 256MB） |
| 4 | 契约策略 | **v1 API 契约全量保留**（路径/AO/VO 字段/Result 包装/错误码/枚举池冻结） | 前端 v1 代码近乎全量复用（只改设置页同步区块与代理目标）；后端是同契约的 TS 重实现，v1 Java 实现 + 68 用例作为业务规则参考 |
| 5 | 账号 | **保留极简账号**（注册/登录/登出/资料，X-Auth-Token 会话） | 有服务端则账号自然成立；user_id 隔离保留（ADR-005 不变） |
| 6 | 多端同步 | **砍掉**（P-02 同步子域整体删除） | 客户端薄在线模式（数据总在服务端，无离线缓存），无同步问题；未来需要再加 |
| 7 | AI 接入 | **服务端 AI 网关**（ADR-010 语义保留：密钥仅服务端，OpenAI 兼容协议适配器 + Mock 渠道；渠道偏好/用量统计不变） | 密钥不出服务器；客户端零密钥逻辑 |
| 8 | MQ | **无 broker**：进程内事件（NestJS EventEmitter），businessType 语义保留为事件名 | 单服务单实例；规模到多实例时再引 Redis/MQ |

## 2. v1 → v3 变更面（对比 v2 作废方案）

| 维度 | v1（已归档） | v3 |
|------|-------------|-----|
| 后端 | Java Spring Boot（JVM，重） | Node/TS/NestJS（轻） |
| 数据 | MySQL 10 表（DDL） | MongoDB 10 collection（文档模型，嵌入策略见 D3） |
| 部署 | JDK+MySQL+systemd 手工 | docker compose（两容器，内存限额） |
| 契约 | HTTP 66 端点 | **同契约冻结**（前端零感知） |
| 账号/AI 网关/渠道偏好/用量 | 保留 | 保留 |
| 多端同步 | P-02 完整实现 | **删除** |
| 前端 | Vue3+Tauri | 复用（settings 去同步区块、代理目标不变） |

## 3. 栈绑定说明（引擎偏差备案）

- 引擎随发栈无 Node/Mongo profile：本次 D3 的后端规约以**自定义 Node API 规约**执行（写入 01-solution/common-spec/06-node-api-conventions.md，含：契约冻结声明、Mongo 文档建模规约、**查询安全规约——所有查询构造仅允许白名单字段映射，禁止客户端输入直接作为查询运算符/投影注入，ID 一律 ObjectId 校验转换**；D4 仍按 vue3-engine spec）
- `ACTIVE_STACKS` 暂维持（vue3-engine 有效、java-microservice 挂载文件无害）；代码阶段的正式重绑（本地 node-nestjs-mongo 栈 profile 化）在实现时处理

## 4. 执行计划（本次 /design 运行）

D1 变更管理（AA/FL/ADR）→ D2（prd-platform 重写 + 其余微调 + domain-model §9）→ D3（8 契约文档 Mongo/事件化 + 06 规约文档）→ D4（settings 去同步）→ Gate 1 重验。

## 5. 复议修订（2026-10-08 晚，用户三项指示）

| # | 原决策 | 修订 |
|---|--------|------|
| 1 | 部署=Docker Compose 两容器 | **宝塔「Node 项目」部署（PM2 守护 + 内存限额）+ 服务器既有 MongoDB 实例（连接串接入）**；Docker Compose 降为备选 |
| 2 | 砍多端同步（ADR-013） | **多端同步保留**：/auth/sync/pull、登录 VO syncCursor、游标扫描（SyncChangeScanner）、settings 同步区块全量恢复；契约冻结范围回到 **v1 全量 66 端点** |
| 3 | 65 端点 | **66 端点**（v1 契约 100% 冻结，前端 v1 代码全量复用含同步交互） |

Mongo 实现注记：同步游标用 Mongo Date（毫秒精度）+ (cursor, id) 复合推进，消除 v1 MySQL 秒精度截断重投的已知问题（at-least-once → 可做到稳定 exactly-once 语义）。
