| 属性 | 值 |
|------|-----|

## 1. 原始需求

> AI 已能直接生成 PPT 类内容，但生成后的调整只能通过自然语言反复进行；这个「语言调整」环节散落在聊天窗口里（无版本对比、无定向修改、上下文易丢失）。做一个客户端软件管理这类「AI 生成 + 语言迭代」的工作。

## 2. 已确认决策（两轮澄清，2026-10-07）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 技术路线 | vue3-engine（Vue3/Vite + Tauri 桌面壳）+ java-microservice（云端服务） |
| 2 | 内容形态边界 | **多形态平台**：演示文稿 + 文档/海报；核心抽象为「创作物 + 类型」 |
| 3 | 首期落地范围 | 架构按多形态抽象，**首期仅实现演示文稿类型**，其余类型后续接入 |
| 4 | 用户与协作 | **个人单用户**；云端账号只做多设备同步与 AI 网关，无协作/分享 |
| 5 | AI 接入 | **多 provider 云端网关**统一收口（密钥不落客户端，provider/模型可配置可切换） |
| 6 | 版本模型 | **版本树 + 分叉**：每次生成/调整自动留档新版本，可预览对比、任意回退、从任意版本分叉 |
| 7 | 语言调整粒度 | **整稿级 + 定向局部级**（选中某页/文本块/图片元素后语言描述局部修改） |
| 8 | 素材/品牌 | 含**素材库与品牌规范**（logo/图片/字体/色板），生成与调整时作为约束注入 |
| 9 | 交付形态 | 可编辑 **PPTX** + **PDF/图片** + **内置演示模式**（三项全要；PPTX 为长期目标，PDF/图片与演示为首期主路径） |

## 3. 业务概念提取

| 维度 | 内容 |
|------|------|
| 业务术语 | 创作物（Deck）、内容版本、语言调整指令、定向目标、品牌规范、素材、话术模板、AI 渠道、生成任务、导出物、定稿 |
| 业务流程 | 建创作物 → 配素材/品牌 → 需求输入 → 大纲生成确认 → 整稿生成 → 语言调整循环（整稿/定向，逐版留档） → 定稿 → 导出/演示 |
| 业务角色 | 创作者（唯一用户类型）；云端另有平台运营视角但不建独立角色 |
| 业务规则 | ① 调整只通过自然语言指令驱动（产品定位核心约束）② 每次生成/调整自动产生新版本且历史版本不可变 ③ 品牌规范在生成/调整时可选用注入 ④ 定稿后锁定编辑，解锁后回到迭代态 ⑤ AI 调用一律经云端网关 |
| 业务数据 | 创作物、版本（含页面快照）、调整指令、素材资产、品牌规范、话术模板、渠道偏好、生成/导出任务、导出记录 |

## 4. 核心实体与状态流转（初判，D1/D2 细化）

- **创作物**：草稿 → 迭代中 → 已定稿 → 已归档（已定稿可解锁回迭代中；已归档可恢复）
- **版本**：不可变快照，组成版本树（parent 边 + 分叉分支）；无状态机
- **生成任务**：排队 → 执行中 → 成功 / 失败 / 已取消（异步子流程，成功产出新版本）
- **导出任务**：排队 → 渲染中 → 成功 / 失败（成功产出导出记录 + 文件）

## 5. 集成关系

| 集成点 | 方式 |
|--------|------|
| AI provider（多家大模型） | 云端网关适配器模式对接，密钥云端托管 |
| 桌面客户端 ↔ 云端服务 | HTTP API（会话鉴权）+ 任务进度轮询/SSE |
| 导出文件 | 云端渲染 → 对象存储 → 客户端下载 |
| 多端同步 | 云端为主数据源，客户端本地缓存 + 拉取同步 |
